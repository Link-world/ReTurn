Each frozen Development stratum contained 125 eligible complete pairs. Within each stratum, candidates were shuffled using the fixed seed. Five pairs were selected by minimum previous target-parent usage, then previous side/modality/family usage, with shuffled order breaking ties. This encourages source and family diversity. The sampler did not read predictions, scores or gaps. No exclusions were needed in the 80-task selection. Pair selections are listed in `preview_manifest.json`.

Original adaptation roles are preserved: **58 ADAPT_TRAIN / 22 ADAPT_VAL** tasks. There is no current frozen Test task in this release. Historical split labels are retained separately as `old_split`: 42 TRAIN, 6 DEV, 32 TEST. The latter describes the earlier split, not the current authoritative Development assignment. This preview is development-exposed material; it is not a fresh, unseen final test set. No new split assignment or question revision was made.

The 8-task quick start takes one complete Short pair from each side/modality cell. It uses the first selected pair whose full request dependency closure is covered by bundled media. During the initial packaging pass, this filter replaced one quick-start pair to select FineVideo-only inputs; it never consulted model results. The companion media package includes all selected clips from both datasets, and retains that quick-start selection and all 80 tasks unchanged. The quick start does not cover Long. `backend_validation_manifest.json` preserves the separate pre-output small compatibility selection, including Short and Long.

## Frozen protocol

Task side pairs `preserve` (Reconfirm/reference) with `revise` (Reground/conflict). Evidence side pairs `retrieve` (reference) with `rebind` (conflict). Each pair retains both operations. The exported questions, answer aliases, ordered options, native requests and necessary-evidence controls come from the final frozen wording contract. Terminology is not used to rebuild messages: the serialized requests are authoritative.

`C` is the frozen Single-turn necessary-evidence view. It is not assumed to be current-only. `H0` is the Multi-turn view, using real native assistant replies generated by the evaluated backend in the recursively specified prefix. Long histories retain all frozen media/user turns and prior generated replies. They are not assembled from independent cached conversations. Native dependencies can be shared only when their complete request identity and run contract are the same.

The formal `task_id` already fixes an operation and horizon. In this release the 80 such IDs are called base tasks. OpenQA/MCQ and Single/Multi are views of those IDs, not additional base tasks. There are 160 logical interface views, 240 unique final C/H0 requests (controls are shared), and 250 unique native dependency requests: 490 physical request contracts overall.

The pool covers V and A evidence requirements; no AV task is claimed. Answer interface and modality are separate fields. The output contract has OpenQA and four-option MCQ views; the release does not infer modality from interface. Single-modality-required tasks can still carry both audio and video for Omni evaluation. Unimodal adapters consume only their channel, following the formal model-specific runtime.

## Files and identities

- `data/tasks/tasks.jsonl`: task/pair IDs, operation, side, modality, horizon, family, original adaptation role, and request references for both interfaces.
- `data/tasks/inputs.jsonl`: inference-only ordered messages. Assistant turns contain `REQUEST_RAW` references, not fixed answers. No gold/alias fields appear here. Frozen question text includes MCQ options where required.
- `data/tasks/answers.jsonl`: gold, aliases, ordered options, interface, and formal scoring question. This file is never loaded by the inference runner.
- `data/media_manifest.json`: stable clip ID, parent/source ID, start/end seconds, portable media paths, upstream license declaration, bundled status, and optional restoration information.
- `data/ATTRIBUTION.json`: source credit, source URL, upstream license declaration and transformations; FineVideo includes the available original title/channel and LLaVA includes dataset-curator credit and exact source members.

The companion media archive supplies all referenced media: **127 clips from 125 parent videos**: 112 FineVideo clips from 110 parents, plus 15 LLaVA clips from 15 parents. A clip and its companion WAV are one input window, not two independent sources. Native histories can introduce sources beyond the target pair. Different windows, shared controls, interfaces, paired operations and history horizons are correlated views, not independent source samples.

## Scoring and denominators

The formal answer normalizer, MCQ parser and judge prompt are copied verbatim into `return_eval/formal.py`. OpenQA strict matching normalizes to lowercase ASCII alphanumeric words and compares frozen accepted answers. MCQ strict matching accepts the correct letter; the formal rule also recognizes one explicit answer letter or the uniquely mentioned correct option text. All rule failures are sent to the blind reviewer or looked up by their full scoring identity. No alias or gold is added to chase a passing score.

Review identity includes the full scoring question, gold, deduplicated aliases, ordered options, interface, exact raw reply, and the formal color-granularity marker when applicable. The judge sees anonymous IDs and answer contracts only. It returns equivalent/incorrect/uncertain, format compliance and a reason. `uncertain` earns no confirmed-correct credit. Review is textual equivalence, not a claim of new media verification. Content-correct means rule-correct or reviewer-equivalent; strict score remains separately available.

Failed inference, empty/truncated replies, failed native dependencies and pending review are explicitly excluded from valid paired accuracy. They are not silently scored wrong. A logical task/interface contributes only when both C and H0 are valid and scored. Groups weight each such logical view equally. OpenQA and MCQ never share an accuracy denominator. Percent-point gap is C minus H0; harm and rescue are paired counts.

Reference/conflict four-cell summaries require both operations to have valid C and H0, so Single and Multi pair comparisons use the same pair IDs. Cells are both-correct, reference-only, conflict-only and both-wrong. Missing pair members are recorded. Physical request counts, base task counts and logical view counts are distinct.

## Limits

The preview is a small, stratified development subset. Its family frequencies and results do not estimate the complete benchmark distribution. Model/API changes, provider configuration and different input encoders can change outputs. Current live checks and historical cache examples are labeled separately. Prior source exposure is retained rather than reset by this release. Short/Long differences here do not isolate history length from media or intervening content. No causal-mechanism, training or final-test claim is made by this preview.

Source media retain their own rights. Annotation licensing and upstream media terms are described in `LICENSE-DATA` and `THIRD_PARTY_MEDIA.md`.
